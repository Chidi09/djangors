# Design 5.2 — Admin changelist v1: generic field rendering, sorting, pagination (Phase 5 part 2)

**Status:** draft, pre-implementation. Second slice of Phase 5. `PLAN.md`'s changelist bullet is
huge ("list_display (fields + computed methods); sorting; pagination; list_filter; search_fields;
date_hierarchy; list_editable; bulk actions incl. CSV/XLSX export; saved views") — this task builds
only the load-bearing core: **a per-model changelist page showing every field as a column, with
column sorting and pagination**. Everything else in that bullet (computed `list_display` methods,
`list_filter`, `search_fields`, `date_hierarchy`, `list_editable`, bulk actions, exports, saved
views) is deferred to later 5.x design docs — they all layer on top of the value-rendering and
route plumbing this task creates, and none of them can exist before it.

## The core problem this task solves

The admin holds registered models only as `Box<dyn ModelAdmin>` exposing `&'static ModelMeta` —
pure metadata. There is **no way today to get displayable values out of a model instance
generically**: no reflection, no `Serialize`, nothing. The derive macro, however, already
generates per-field value-extraction code for save/update binds
(`crates/djangors-macros/src/model.rs` ~lines 493–535, the `save_binds` per-type `match` producing
`djangors_orm::expr::Value::from(self.#ident ...)` tokens). That existing match arms handle every
supported field type (String clone, `i32 as i64`, `f32 as f64`, passthrough for i64/f64/bool/
DateTime, `Option<T>` → `Value::Null`, relations → `Value::from(self.#ident.id)`), and the derive
**already rejects at compile time** every type `Value` can't hold (NaiveDate/NaiveTime/Duration/
Uuid/Decimal — see the "unsupported types for save/update/delete codegen" check ~line 324). So the
generic display path is: **derive emits a `field_values()` method reusing the save-binds match
logic**, and the admin renders `Value`s as strings.

## Part 1 — `djangors-orm`: `Value` display + `Model::field_values`

1. `impl std::fmt::Display for Value` (`crates/djangors-orm/src/expr.rs`): `I64`/`F64`/`Bool`/
   `Text` via their own `Display`; `DateTime` as `v.format("%Y-%m-%d %H:%M:%S")` (UTC, matches
   Django admin's plain rendering); `Null` as `-` (Django's empty-value display default).
2. Add a **required** method to the `Model` trait (`crates/djangors-orm/src/meta.rs` line 186):

   ```rust
   /// Every field's (field_name, current value) in declaration order,
   /// including primary-key/auto fields (unlike save binds, which skip
   /// auto fields) and FK fields (as the related id). Generated by
   /// #[derive(Model)]; the admin changelist renders rows through this.
   fn field_values(&self) -> Vec<(&'static str, crate::expr::Value)>;
   ```

   Required, **not** defaulted-to-empty — a default would make a hand-written `Model` impl
   silently render zero columns. The only hand-written impls in the workspace are the two
   test-only ones in `crates/djangors-orm/src/tests.rs` (`FictionalModel`, `RelatedModel`) —
   give them honest small impls listing their fields.

## Part 2 — `djangors-macros`: derive emits `field_values`

In `expand_derive_model` (`crates/djangors-macros/src/model.rs`), emit `field_values()` inside the
existing `impl Model` block. Build the per-field tokens with the **same match structure as
`save_binds`** (factor the shared per-field value-expression generation into one helper used by
`save_binds`, `update_binds`, and the new `field_values` — the three currently-duplicated match
blocks at ~493 and ~551 are already copy-paste twins; don't add a third copy), but over **all**
fields in declaration order: primary key and `auto` fields included, relation fields as
`(field_name, Value::from(self.#ident.id))`. Tuple entries use the *field* name (`f.name`, what
`order_by` validates against), not the column name.

## Part 3 — `djangors-core`: promote `html_escape`

`html_escape` (`crates/djangors-core/src/debug_page.rs` line 238) is private. Changelist cell
values are **user data** (usernames, poll questions) — rendering them unescaped is stored XSS.
Move the function to a small `pub fn html_escape(input: &str) -> String` exported from
`djangors-core`'s lib.rs (keep `debug_page.rs` using it via the new path; no behavior change,
same replacement set `& < > " '`). Do not add a dependency for this.

## Part 4 — `djangors-admin`: the changelist route

1. **Registry becomes `Mutex<Vec<Arc<dyn ModelAdmin>>>`** (was `Box`) so `urls()` can clone the
   admins into route-handler closures — same closure-capture pattern (and same reason: `mount`
   never carries sub-router state) as 5.1's index snapshot, documented on `urls()` already.
2. **`ModelAdmin` grows an object-safe async data method** (`#[async_trait]`, dependency
   `async-trait = "0.1.86"` — the version already declared elsewhere in the workspace):

   ```rust
   pub struct ChangelistPage {
       pub columns: Vec<&'static str>,          // field names, declaration order
       pub rows: Vec<Vec<String>>,              // Display-rendered, NOT escaped (view escapes)
       pub total: i64,                          // COUNT(*) over the whole table
       pub page: i64,                           // 1-based current page
       pub per_page: i64,
   }

   #[async_trait]
   pub trait ModelAdmin: Send + Sync {
       fn model_meta(&self) -> &'static ModelMeta;
       async fn changelist(
           &self,
           db: &djangors_db::Database,
           order: Option<&str>,   // raw ?o= value, e.g. "name" or "-name"
           page: i64,             // already-validated >= 1
           per_page: i64,
       ) -> Result<ChangelistPage, DjangorsError>;
   }
   ```

   `DefaultModelAdmin<M>` implements it via the real typed QuerySet: start from `M::objects()`,
   apply `.order_by(o)?` only when `order` is `Some` (when `None`, the queryset already applies
   `meta.ordering` by itself — `queryset.rs` ~line 141), map `OrmError::FieldNotFound` from a bad
   `?o=` to `DjangorsError::BadRequest` (variant exists, `error.rs` line 13), then
   `.limit(per_page).offset((page - 1) * per_page)`, `.all(db)` for rows +
   `M::objects().count(db)` for `total`, rows rendered `instance.field_values()` →
   `value.to_string()`. This needs `M: Model + FromRow + Send + Sync` bounds on the
   `DefaultModelAdmin` impl (match whatever bound `QuerySet::all` actually requires — read
   `queryset.rs`, don't guess). `djangors-admin` gains a real (non-dev) `djangors-db` path
   dependency — it's already a dev-dependency, just promote it.
3. **Routes.** `urls()` keeps GET `/` (index) and adds:

   ```rust
   .get("/{app:slug}/{model:slug}/", /* closure capturing Vec<Arc<dyn ModelAdmin>> */)
   ```

   Lookup key: `app` == `meta.app_label`, `model` == `meta.struct_name.to_lowercase()` (Django's
   URL convention, e.g. `/admin/polls/question/`). Linear scan of the captured Vec is fine at
   registry sizes. No match → `DjangorsError::NotFound`. The **index page** changes its `<li>`
   entries into relative links `<a href="{app}/{model}/">` — relative (no leading slash) so they
   work under any mount prefix... **check `Response::html` + browser-relative-URL semantics
   carefully: index is served at the mount root `/admin/` (trailing slash), so a relative
   `polls/question/` resolves to `/admin/polls/question/` — correct.** Keep it relative; do not
   hardcode `/admin`.
4. **Handler** (`admin_changelist`): staff gate first — identical `Auth::<User>` + `is_staff`
   check as `admin_index` (factor the gate into a small `async fn require_staff(&Request) ->
   Result<(), DjangorsError>` used by both handlers). Then parse query params from
   `req.query()`-equivalent (check the real `Request` query API in `djangors-core` — the fuzz
   target `fuzz/fuzz_targets/query_string.rs` calls `.query()`): `o` (optional string), `page`
   (optional, parse as i64, default 1; `< 1` or unparseable → `BadRequest`). `per_page` fixed
   constant `100` (Django's default), not configurable in v1. Call `admin.changelist(...)`,
   render a plain HTML table: header row of column names each wrapped in a sort link
   (`?o={name}`, flipping to `?o=-{name}` when that column is the current ascending sort), body
   cells through `djangors_core::html_escape`, and a footer pager: total count, current page,
   `Previous`/`Next` links (`?page={n}`, preserving the current `o` param) shown only when the
   respective page exists. Plain `format!` HTML like the index — no `djangors-template`
   integration yet (theming is a later Phase 5 bullet).

## What this task does NOT include

- `list_display` customization / computed display methods, `list_filter`, `search_fields`,
  `date_hierarchy`, `list_editable`, bulk actions, CSV/XLSX export, saved views — all later
  5.x slices layered on this one.
- Change form / detail pages — the changelist rows are **not** links yet (Django links the first
  column to the change form; there is no change form to link to). Plain text cells.
- FK display beyond the raw id (Django shows `__str__` of the related object; we have no
  `Display`-for-model convention yet — defer, render the id).
- Making `dj`/`examples/polls` use the admin — still deferred until the admin is usable enough
  to demo (changelist alone probably clears that bar; wiring it into polls is its own tiny
  follow-up task, not part of this one).

## Required tests

- **orm/macros:** unit test that a derived model's `field_values()` returns every field in
  declaration order with correct `Value`s, including the pk/auto field, an `Option` field as
  `Value::Null` when `None`, and an FK field as the related id (extend the existing macro/orm
  test models rather than inventing new crates). `Value` Display: one assert per variant
  including DateTime formatting and `Null` → `-`.
- **admin** (extend `crates/djangors-admin/src/lib.rs` tests, same real-Postgres + mounted-router
  pattern as `test_admin_index_endpoints` — keep routing through `Router::new().mount("/admin",
  site.urls())`, per that test's own doc comment about why):
  - staff GET `/admin/{app}/{model}/` → 200; body contains header cells for every field name and
    the escaped values of seeded rows (seed one row whose text field contains
    `<script>alert(1)</script>` and assert the body contains the escaped form and **not** the
    raw `<script>` string — the XSS regression test).
  - default order honors the model's `ordering` meta; `?o=-{field}` reverses a seeded 2-row
    order; `?o=nonsense` → 400.
  - pagination: seed 3 rows, per-page override is not configurable so instead assert page math
    via `?page=2` with the constant — **no**: 101 seeded rows is slow/ugly. Instead make the
    per-page constant a `pub(crate) const CHANGELIST_PER_PAGE: i64` and have the *trait method*
    take `per_page` (it already does, per the signature above) so the test can call
    `admin.changelist(&db, None, 2, 2)` directly for the page-math assertions (rows 3 of 5,
    correct `total`), plus one HTTP-level assert that `?page=2` with the real constant and few
    rows returns 200 with an empty body table and a working `Previous` link.
  - unauthenticated → 401, non-staff → 403 (reuse the existing session-injection pattern),
    unknown `/admin/nope/nope/` as staff → 404.
- Full workspace green: `cargo fmt --all`, `build --workspace`, `clippy --workspace --all-targets
  -- -D warnings`, `test --workspace`.
