# 5.8 part 6 — Convert the changelist page (`admin_changelist`) to a template

**Status:** design, not yet dispatched. Follows 5.8.5 (add/change form, commit `55e54b5`). See
`docs/design/phase-5-roadmap.md`. This is the last and by far the biggest/most complex page in
the 5.8.x arc — every simpler page has proven the "flatten to plain structs in Rust, template
only loops/switches on tags" mechanism, and this slice applies it to a page with ~8 independently-
conditional sub-sections. Read `admin_changelist`'s current body directly (`crates/djangors-admin/
src/lib.rs`, `fn admin_changelist`) before implementing — this doc describes it from a prior
reading, but every byte-level detail must be verified against the real source, since the tests
this task must keep passing check specific substrings.

## Scope: only `admin_changelist`'s HTML-building tail

Everything before the HTML assembly is unchanged: `parse_changelist_query_state`, the
`admin.changelist(...)` call producing `page_data: ChangelistPage`, and all of the pre-existing
helper functions (`build_query_string`, `url_encode_query_value`, `get_month_name`,
`date_hierarchy_drilldown_values`). **Do not touch any of those.** This task converts the part of
`admin_changelist` that builds `header_html`, `body_html`, `pager_html`, `search_html`,
`filter_html`, `date_hierarchy_html`, `action_buttons`, `export_html`, and the final `format!()`
assembling them into `html`, replacing the tail `Ok(Response::html(StatusCode::OK, html))` with a
template render.

## The key risk-reducing decision made in this design: no `Safe`-wrapping anywhere on this page

Every prior 5.8.x slice that built a URL either used `Value::from_safe_string` (5.8.1, for
compile-time-only strings) or restructured the template to avoid needing it (5.8.4's
segment-substitution pattern). **This page cannot use 5.8.4's segment pattern** for most of its
links, because `build_query_string()` joins a *variable* number of query pairs with a literal,
un-escaped `&` (e.g. `?o=name&q=foo&is_active=true`) — there's no fixed set of "segments" to write
as static template markup around.

The choice made here, after checking it against every existing test assertion in this file
(confirmed by grep — no test anywhere checks for a raw, un-escaped `&` between two query
parameters in an href): **treat every href on this page as a plain, ordinary-autoescaped `String`
field, the same as any other dynamic value.** This means minijinja's autoescape will render the
structural `&` between query pairs as `&amp;` — which is *not* byte-identical to the current
`format!()` output, but:

1. `build_query_string()` already percent-encodes every *value* it embeds (via
   `url_encode_query_value`, see the function's own doc comment on why — untrusted values like the
   search term can never contain a raw `&`/`<`/`>`/`"`/`'` to begin with), so autoescaping a
   percent-encoded value is always a no-op on the value itself; the only thing that changes is the
   *unescaped* `&`/`=`/`?` structural characters, which are always built from static `&'static
   str` keys, never user input.
2. Un-escaped `&` inside an HTML attribute value is technically invalid HTML (browsers tolerate it
   universally, but `&amp;` is the spec-correct form) — so entity-encoding it is a strict
   correctness improvement, not a regression.
3. **No existing test's assertions depend on the raw, un-escaped form** — confirmed directly:
   `test_admin_changelist_endpoints` only checks single-pair links like `<a href="?o=id">id</a>`
   (no second pair present, so no `&` appears either way); `test_phase5_list_filter` checks
   `<a href="?is_active=true">Yes</a>` (again a single pair); `test_phase5_part6_4_date_hierarchy`'s
   test 5 checks `body5.contains("year=2026")` — a substring that appears identically whether the
   surrounding href is `?o=name&year=2026` or `?o=name&amp;year=2026`, since `"year=2026"` doesn't
   contain the ampersand itself. No test anywhere in this file asserts on a literal, un-escaped
   `&` between two params.

**This means every `href`/`value`/`label` field defined below is a plain `String` (or
`Option<String>`), never `minijinja::value::Value::from_safe_string`.** This is a deliberate
decision specific to this page (unlike 5.8.1's `href`/`label`, which stayed `Safe` because they
were compile-time constants where entity-encoding `/` really would have changed a test-asserted
substring). State this reasoning as a code comment above the new context structs, since it's the
single most important judgment call in this slice and a future reader converting a *different*
page with query-string links needs to know this precedent exists and why.

## Section-by-section: current `format!()` shape → new struct

Read the real source for exact whitespace on every one of these before writing the template — the
descriptions below are a guide, not a substitute for reading `admin_changelist` directly.

### 1. Header row (`header_html`)

For each `page_data.columns` entry: an `<a>` toggling sort order (prefixing `-` if this column is
the current `o`), carrying forward `q`/active filters/year/month/day. Preceded by one static
`<th></th>` (the checkbox column has no header).

```rust
#[derive(serde::Serialize)]
struct HeaderCellData {
    href: String,
    label: String, // the column name, e.g. "name" — never contains HTML metacharacters
}
```

### 2. Body rows (`body_html`)

Each row: a checkbox `<td>` (value = pk), then one `<td>` per display column. Column 0 is *always*
a link to the change page (`{pk}/change/`, a bare relative path — no query string, no `&`, so this
one specific `href` can stay `{{ row.pk }}/change/` built from static template text + the plain
`pk` field, matching 5.8.4's segment-substitution style exactly since it has no `&` problem).
Every other column is either an inline-editable `<input>` (if in `list_editable_fields()`) or a
plain `<td>` — **column 0 takes priority over "is this field in list_editable_fields()"**, i.e. a
field named as column 0 is never rendered as editable even if it's also present in
`list_editable_fields()` — preserve this exact `if i == 0 { .. } else if editable { .. } else {
.. }` priority order, don't reorder it.

```rust
#[derive(serde::Serialize)]
struct ChangelistCellData {
    kind: &'static str,  // "pk_link" | "editable" | "plain"
    value: String,        // raw (un-escaped) display text; template's autoescape handles it
    field_name: String,   // only meaningful when kind == "editable" (empty string otherwise)
}

#[derive(serde::Serialize)]
struct ChangelistRowData {
    pk: String,           // page_data.pks[row_index], already a String
    cells: Vec<ChangelistCellData>,
}
```

### 3. Pager (`pager_html`)

`<a>Previous</a> ` (only if `page > 1`, note the trailing space) + `"Page {page} of {total_pages}.
Total: {total}. "` (note the trailing space) + `<a>Next</a>` (only if there's a next page, no
trailing content after).

```rust
#[derive(serde::Serialize)]
struct PagerData {
    prev_href: Option<String>,
    page: i64,
    total_pages: i64,
    total: i64,
    next_href: Option<String>,
}
```

### 4. Search box (`search_html`)

Only rendered at all if `search_fields()` is non-empty. `<form method="get">` + a hidden input for
`o` (only if `Some`) + one hidden input per active filter + hidden inputs for `year`/`month`/`day`
(only if `Some`, in that exact order) + the visible `q` text input + submit + `</form>`.

```rust
#[derive(serde::Serialize)]
struct HiddenInputData {
    name: String,
    value: String,
}

#[derive(serde::Serialize)]
struct SearchBoxData {
    visible: bool,
    hidden_inputs: Vec<HiddenInputData>, // exact order: o (if present), then filters, then year/month/day
    q_value: String,
}
```

### 5. `list_filter` blocks (`filter_html`)

One block per `list_filter_fields()` entry: `<div>Filter by {field}:` then a **literal newline and
two-space indent** before each of three `<a>` links (All/Yes/No), then a literal newline before
the closing `</div>`. **This is the one place on this page where the template file must contain
real newline characters, not stay on one line** — that whitespace is part of the current output
(confirmed by reading the `format!()` string's literal `\n  ` sequences directly) and nothing
requires collapsing it now; preserve it exactly, in the template's actual source bytes, not as an
escape sequence.

```rust
#[derive(serde::Serialize)]
struct FilterBlockData {
    field: String,
    all_href: String,
    yes_href: String,
    no_href: String,
}
```

### 6. Date hierarchy (`date_hierarchy_html`)

Only rendered at all if `admin.date_hierarchy_field()` is `Some`. `<div class="date-hierarchy">` +
breadcrumbs (joined with `" &rsaquo; "` between entries) + (`" &rsaquo; "` again, but *only* if
**both** breadcrumbs and drilldown-links are non-empty) + drilldown links (joined with `" | "`
between entries) + `</div>`. Read the real source's breadcrumb-building `if let Some(y) = year {
if let Some(m) = month { if let Some(d) = day { ... } else { ... } } else { ... } }` nesting
directly — do not guess at it — and preserve it exactly when building `breadcrumbs: Vec<...>` in
Rust (this nesting decides how many breadcrumb entries exist and what each one links to/displays).
Same for the drilldown-links loop, which is skipped entirely once `day.is_some()`.

```rust
#[derive(serde::Serialize)]
struct DateHierarchyLinkData {
    href: String,
    label: String, // a year/day number as a string, or a month name — plain text either way
}

#[derive(serde::Serialize)]
struct DateHierarchyData {
    visible: bool,
    breadcrumbs: Vec<DateHierarchyLinkData>,
    links: Vec<DateHierarchyLinkData>,
}
```

The join-with-separator-only-between-entries behavior is implemented in the template with
`{% if not loop.last %}...{% endif %}` inside each `{% for %}`, and the breadcrumbs/links
separator with `{% if date_hierarchy.breadcrumbs and date_hierarchy.links %}...{% endif %}`
(minijinja treats a non-empty list as truthy, matching Jinja2 semantics — confirm this actually
renders correctly for both the empty and non-empty cases as part of verification, don't assume).

### 7. Action buttons (`action_buttons`)

Always a "Delete selected" button; a second "Save" button only if `list_editable_fields()` is
non-empty.

```rust
show_save_button: bool, // top-level context field, not its own struct
```

### 8. Export link (`export_html`)

`<a href="export-csv/{query}">Export CSV</a>` where `{query}` is `build_query_string(...)` (empty
string or `"?..."`). Keep `"export-csv/"` as static template text (it never varies) and only the
query part as a plain `String` context field — same reasoning as every other href on this page.

```rust
export_query: String, // top-level context field
```

## Top-level context struct and assembly order

```rust
#[derive(serde::Serialize)]
struct ChangelistTemplateContext {
    date_hierarchy: DateHierarchyData,
    search: SearchBoxData,
    list_filter_blocks: Vec<FilterBlockData>,
    header_cells: Vec<HeaderCellData>,
    rows: Vec<ChangelistRowData>,
    show_save_button: bool,
    pager: PagerData,
    export_query: String,
}
```

The current final `format!()` is:
```
"{date_hierarchy_html}{search_html}{filter_html}<form method=\"post\" action=\"bulk-delete/\"><table><thead><tr>{header_html}</tr></thead><tbody>{body_html}</tbody></table>{action_buttons}<div>{pager_html}{export_html}</div></form>"
```
Reproduce this exact ordering and nesting in the template.

contain real newline + two-space-indent characters exactly as shown (see section 5). Verify this

especially: the space after `</a>` in the "Previous" link; the two trailing-space sentences in the
pager text; the exact `&rsaquo;`/`|` join separators and when each one appears.

## `render_form` precedent for the handler change
