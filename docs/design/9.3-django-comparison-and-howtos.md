## Part A — "Djangors for Django developers" (`docs/src/django-comparison.md`)

A single, focused, side-by-side reference: for each thing an experienced Django developer already
knows how to do, show the Djangors equivalent, called out explicitly where the shape or guarantees
differ (not just a syntax rename). Structure as a table or side-by-side code-block pairs, whichever
reads better in mdBook's rendered HTML — pick one and be consistent throughout.

**The same non-negotiable rule as 9.1/9.2 applies**: every Djangors-side code snippet must be
checked against real, current source (the same crates/files 9.2 already read: `djangors-orm`,
`djangors-macros`, `djangors-core`, `djangors-auth`, `djangors-admin`, `djangors-cli`) before being
written down — do not write a snippet from memory of "what the Rust equivalent probably looks
like." The Django side can be written from well-known, stable Django API knowledge (`models.Model`,
`urls.py`, `views.py`, `admin.py`, `settings.py`, `manage.py`) since that's an external, unchanging
reference, not something to verify against this repo.

Cover at minimum (expand if a natural comparison point is missing, but don't pad):
- `models.Model` class + `Meta` → `#[derive(Model)]` + `#[djangors(...)]` attributes
- `urls.py`'s `path()` list → `Router::new().get()/.post()` chains
- `views.py` function views → Djangors's `async fn(Request, PathParams) -> Result<Response,
  DjangorsError>` signature
- `manage.py migrate`/`makemigrations`/`createsuperuser`/`runserver`/`test`/`shell`/`dbshell` →
  `dj migrate`/`makemigrations`/`createsuperuser`/`run`/`test`/`shell`/`dbshell` (note
  `makemigrations`'s real structural limitation, confirmed in 6.3 — don't imply full parity if it
  doesn't exist)
- `admin.py` `ModelAdmin` registration/`list_display`/`list_filter` → `AdminSite::register_with()`
  + `ModelAdminConfig`
- `settings.py` → `DjangorsSettings`/environment-variable loading
- Django's `{% csrf_token %}` + middleware → Djangors's `csrfmiddlewaretoken` hidden field +
  `csrf_layer()` (note the real mechanism from 5.8.9/5.8.10: header-first with a form-body
  fallback, not identical to Django's approach — describe what's actually implemented)
- Django forms (`forms.Form`/`ModelForm`) → Djangors's `Form<T>` extractor (note: no
  `ModelForm`-equivalent auto-generation exists — say so if true, verify against
  `djangors-core/src/extract.rs` first)
- Django REST Framework `ModelSerializer`/`ViewSet` → `djangors-rest`'s `serialize`/`deserialize`
  + `ViewSet<M>` (verify against `crates/djangors-rest/src/lib.rs`)
- Key **conceptual** differences worth a dedicated callout: async-by-default, compile-time type
  checking of models/queries vs. Python's runtime duck typing, no auto-reload without `dj run`'s
  watch loop parity check (verify current behavior), the single-binary deployment model vs.
  Django's WSGI/ASGI + separate static-file serving story.

## Part B — how-tos (`docs/src/how-to/`)

Short, task-focused recipes — "how do I do X" — distinct from the tutorial (linear, builds one app
step by step) and the topic guides (comprehensive per-subsystem reference). Each how-to should be
answerable in under a screen of content: a problem statement, a real verified code snippet, done.
Pick a reasonable set covering common real tasks not already fully covered by the tutorial/guides,
e.g.:
- How to add a custom admin action (`AdminAction`, verify against `djangors-admin`)
- How to send an email (`djangors-mail`'s `SmtpBackend`/`FileBackend`, verify against
  `crates/djangors-mail/src/lib.rs`)
- How to cache a view (`djangors-cache`'s `CacheLayer`, verify against
  `crates/djangors-cache/src/lib.rs` — note the deliberate opt-in-only, no-`Set-Cookie` caching
  restriction found during Phase 7)
- How to add a background task (`#[task]` macro + `Worker`, verify against `djangors-tasks`)
- How to stream Server-Sent Events (`Response::sse`/`Router::sse()`, verify against 8.4's real
  implementation — and note the real v1 limitation that SSE only works via the plain `serve`/`run`
  path, not `run_service()`)
- How to internationalize a template (`djangors-i18n`'s `trans` filter, verify against
  `crates/djangors-i18n/src/lib.rs`)

Pick 5-8 real, well-verified how-tos rather than padding to an arbitrary count — quality and
accuracy over coverage breadth, matching every prior 9.x slice's own standard.
