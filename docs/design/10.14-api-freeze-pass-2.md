## The real work

Same 4-way classification as pass 1, for every `pub` top-level item in each of the 22 crates
above:

1. **Keep public as-is** — genuinely part of the intended stable API surface.
2. **`pub(crate)`** — an internal implementation detail currently fully public by mistake, with no
   legitimate reason for downstream code to use it directly. Before reclassifying anything this
   way, grep the ENTIRE workspace (not just the crate itself) for external usage — pass 1 found a
   real case (`djangors_core::html_escape`) where an item that looked internal-only was actually
   depended on by a different, out-of-scope crate; don't repeat that mistake by trusting a
   single-crate grep.
3. **`#[doc(hidden)]`** — needs to stay technically `pub` (cross-crate internal use, or generated
   macro code) but shouldn't appear in the documented public contract.
4. **Flag for a human decision** — genuinely ambiguous; add a `// FREEZE-REVIEW:` comment
   explaining the ambiguity. Every item must get one of these four outcomes — none left silently
   unclassified.

Be conservative: when genuinely unsure, use bucket 4, don't guess at 2 or 3 for something that
might be load-bearing for existing users. A real usage in `examples/school`, `examples/polls`,
the tutorial, or a topic guide is a strong signal an item should stay public.

## Deliberate exclusions

No `#[deprecated]` attributes added anywhere (nothing to deprecate yet pre-1.0). No version bump,
no crates.io publish. No changes to `djangors-core`/`djangors-orm`/`djangors-rest` (already
audited in pass 1 — if you notice something there worth revisiting, flag it in your summary rather
than touching it in this dispatch).

## Required verification

- `cargo doc --workspace --no-deps` must stay at zero warnings (`#![deny(missing_docs)]` is
  already enforced everywhere — a `pub` → `pub(crate)` conversion must not orphan a doc comment
  elsewhere, including an intra-doc link in a DIFFERENT crate than the one you're editing).
- `cargo build --workspace --all-targets` and `cargo clippy --workspace --all-targets -- -D
  warnings` clean — a visibility change can silently break `examples/school`, `examples/polls`, or
  any of the other 25 crates depending on the one you're editing; their actually compiling is the
  real check, not an assumption. Given how many crates depend on each other in this workspace,
  run a full `cargo build --workspace --all-targets` after EVERY crate you finish, not just once
  at the very end, so a break is caught close to its cause.
- `cargo test --workspace` clean.
- If `cargo public-api` or `cargo semver-checks` is already installed (check first; don't spend
  significant time installing new tooling if it isn't readily available — note in your summary if
  you skip this for that reason), run it and note what changed.
- In your final summary, list per-crate: how many items were reclassified into each of the 4
  buckets (rough counts are fine). If you find any case similar to pass 1's `html_escape` (an item
  you initially assumed was safe to seal but a cross-workspace grep revealed a real external
  dependent), name it explicitly and describe how you resolved it.

Print `DONE_MARKER_10_14_API_FREEZE_PASS_2` when finished (or when stopping early — say exactly
