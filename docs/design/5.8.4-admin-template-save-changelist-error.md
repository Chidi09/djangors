# 5.8 part 4 — Convert the `list_editable` save-error page to a template

**Status:** design, not yet dispatched. Follows 5.8.3 (bulk-delete confirm template, commit
`965fb24`). See `docs/design/phase-5-roadmap.md`. Same discipline as every prior 5.8.x slice: one
page, byte-identical output, no visual changes, proven by the existing test passing unmodified.

## Scope: only the error-response branch of `admin_save_changelist_post`

`admin_save_changelist_post` (`crates/djangors-admin/src/lib.rs`, the `list_editable` save
handler from 5.6.5) has two response shapes: a bare `Response::redirect(...)` when every edited
row saved successfully (`if row_errors.is_empty() { ... }` — no HTML, nothing to convert), and an
HTML error listing when at least one row failed validation (the rest of the function, building
`items_html`/`html` and returning `Ok(Response::html(StatusCode::OK, html))`). **This task
converts only the error-listing branch.** Everything before it (params, admin/db resolution,
`require_perm`, form parsing, the per-pk `update_fields_from_form` loop building `row_errors`) is
unchanged.

## A cleaner way to handle the `app`/`model` URL segments — no `Safe`-wrapping needed this time

5.8.1's `admin_index` needed `minijinja::value::Value::from_safe_string` for its `href` field
because the *entire* URL (including the `/` separators) was built as one Rust `String` and
substituted into the template as a single variable — and minijinja's autoescape escapes `/` as
`&#x2f;`, which would have corrupted that pre-built string. **This page doesn't have that
problem, if the template is structured correctly**: the current implementation's `<a
href="/{}/{}/">Back to changelist</a>` only needs `app` and `model` substituted *individually*
into literal template markup that already contains the `/` characters as part of the template's
own static text — not as part of a Rust-built string being substituted whole. Autoescaping a bare
`app`/`model` value (e.g. `"admin_test"`, `"modela"` — path segments, never containing `/`
themselves) is a no-op either way. **Keep `app`/`model` as plain `String` context fields, write
the `/` characters directly in the template's markup around `{{ app }}`/`{{ model }}`, and no
`Safe`-wrapping is needed anywhere in this task** — this is the preferred pattern going forward
whenever a template needs to build a URL from parts: substitute path *segments* into literal
template markup, don't pre-assemble the whole URL string in Rust and substitute it as one value.

## Template file: `crates/djangors-admin/templates/admin/save_changelist_error.html`

```html
<p>Some rows could not be saved (rows without errors were saved):</p><ul>{% for e in errors %}<li>Row {{ e.pk }}: {{ e.field }}: {{ e.message }}</li>{% endfor %}</ul><a href="/{{ app }}/{{ model }}/">Back to changelist</a>
```

One continuous line, matching the existing three templates' convention. Must reproduce the
current `format!()` call's output byte-for-byte. Note: the current Rust source spans that
`format!()`'s string literal across two lines with a trailing `\` before the newline
(`"...</ul>\` then `         <a href=...`) — this is Rust's string-literal line-continuation
syntax, which strips the newline *and* all leading whitespace on the following line, so the
actual produced string has **zero** whitespace between `</ul>` and `<a href` (confirmed by
reading the source directly, not assumed) — matching this template's own single continuous line
with no gap.

## Context structs and the handler change

```rust
#[derive(serde::Serialize)]
struct SaveChangelistErrorRow {
    pk: i64,
    field: String,
    message: String,
}

#[derive(serde::Serialize)]
struct SaveChangelistErrorContext {
    errors: Vec<SaveChangelistErrorRow>,
    app: String,
    model: String,
}
```

Replace the nested `for (pk, errors) in &row_errors { for (field, msg) in errors { ... } }`
loop (currently building `items_html`) with the equivalent flattened loop pushing
`SaveChangelistErrorRow { pk: *pk, field: field.clone(), message: msg.clone() }` into a
`Vec<SaveChangelistErrorRow>` (one entry per `(pk, field)` error pair, same iteration order the
current nested loop already produces — do not reorder or deduplicate). Replace the final
`Ok(Response::html(StatusCode::OK, html))` with `djangors_template::render(&ADMIN_TEMPLATES,
"admin/save_changelist_error.html", SaveChangelistErrorContext { errors, app: app.to_string(),
model: model.to_string() })`.

## `ADMIN_TEMPLATES`: add the fourth entry

Same `from_embedded` call, one more `(name, include_str!(...))` pair:
`("admin/save_changelist_error.html", include_str!("../templates/admin/save_changelist_error.html"))`.
