# 13.1 — SQLite backend (dual-backend foundation)

## Why

Djangors is Postgres-only. Django abstracts four backends, and a single-backend ORM
caps how far the framework can be taken seriously. SQLite also makes the test suite
cheap: no server, no disk-hungry cluster, no `DATABASE_URL` precondition.

## Why not `sqlx::Any`

Ruled out, verified against the vendored source at
`~/.cargo/registry/src/*/sqlx-core-0.9.0/src/any/value.rs`. `AnyValueKind` is
`Null | Bool | SmallInt | Integer | BigInt | Real | Double | Text | TextSlice | Blob`
— there is **no chrono/`DateTime` support at all**, and `FieldKind::DateTime` is used
across every model in this workspace. `Any` also does not normalise placeholder
syntax. Do not attempt this route.

## Architecture: enum dispatch, not generics

Making `QuerySet`/`FromRow`/the derive macro generic over `sqlx::Database` means
propagating `DB: Database, for<'r> i64: Decode<'r, DB> + Type<DB>, …` bounds through
every method, the derive macro, and every downstream crate. That is not tractable
here.

Instead: a `Dialect` enum picks SQL syntax, and two small enums (`Conn`, `DbRow`)
wrap the driver-specific types. Dispatch is a runtime `match` in one crate rather
than a type parameter everywhere.

### The central change: `Conn` takes SQL + params, not a built `Query`

Today `queryset.rs` builds `sqlx::query(sql)` (which is
`Query<'_, Postgres, PgArguments>`), binds parameters through **eight duplicated
`match val { … }` blocks**, and hands the result to `Conn`. A pre-built `Query` is
driver-typed, so it cannot cross a backend boundary.

`Conn`'s methods must therefore take `(sql: &str, params: &[BindValue])` and do the
binding internally, once per backend. This *deletes* all eight duplicated bind
blocks in `queryset.rs` and the four in the derive macro — a real simplification, not
just a port.

## Section 1 — `djangors-db`: dialect, bind values, rows

New `crates/djangors-db/src/dialect.rs`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Dialect { Postgres, Sqlite }

impl Dialect {
    /// `$1`, `$2`, … for Postgres; `?` for SQLite.
    pub fn placeholder(&self, index: usize) -> String;
    /// `ILIKE` for Postgres; `LIKE` for SQLite (whose LIKE is already
    /// ASCII-case-insensitive, so this is the correct equivalent, not a downgrade).
    pub fn ilike(&self) -> &'static str;
    /// `"name"` both dialects (SQLite accepts double-quoted identifiers).
    pub fn quote_ident(&self, name: &str) -> String;
    /// `::float8` for Postgres; `CAST(… AS REAL)` shape for SQLite.
    pub fn cast_float(&self, expr: &str) -> String;
}
```

New `BindValue` in `djangors-db` (djangors-orm depends on djangors-db, not the
reverse, so `orm::Value` cannot be referenced here):

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum BindValue {
    I64(i64), F64(f64), Text(String), Bool(bool),
    DateTime(chrono::DateTime<chrono::Utc>),
    /// Typed NULL — Postgres rejects a mismatched parameter type even for NULL,
    /// which is what `NullBindKind` in queryset.rs already exists to handle.
    Null(NullKind),
}
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum NullKind { I64, F64, Text, Bool, DateTime }
```

`djangors-orm` gets `impl From<Value> for BindValue`. `Value::List` must never reach
here — it is expanded into scalars by `compile_expr_sql` — so the conversion maps it
to `Null(NullKind::I64)` with a comment, exactly as the current bind sites do.

New `DbRow`:

```rust
pub enum DbRow { Pg(sqlx::postgres::PgRow), Sqlite(sqlx::sqlite::SqliteRow) }

impl DbRow {
    pub fn try_i64(&self, idx: usize) -> Result<Option<i64>, sqlx::Error>;
    pub fn try_f64(&self, idx: usize) -> Result<Option<f64>, sqlx::Error>;
    pub fn try_string(&self, idx: usize) -> Result<Option<String>, sqlx::Error>;
    pub fn try_bool(&self, idx: usize) -> Result<Option<bool>, sqlx::Error>;
    pub fn try_datetime(&self, idx: usize)
        -> Result<Option<chrono::DateTime<chrono::Utc>>, sqlx::Error>;
    // by-name variants, same set, suffixed `_by_name`
    pub fn try_i64_by_name(&self, name: &str) -> Result<Option<i64>, sqlx::Error>;
    // … etc
}
```

Both index and name variants are required: the derive macro reads columns by name,
`decode_value`/`annotate` read by index.

## Section 2 — `Conn` and `Database`

`Conn` becomes four-way:

```rust
pub enum Conn<'a> {
    PgPool(&'a sqlx::PgPool),
    PgTx(&'a mut sqlx::PgConnection),
    SqlitePool(&'a sqlx::SqlitePool),
    SqliteTx(&'a mut sqlx::SqliteConnection),
}
```

Methods change signature to:

```rust
pub async fn fetch_all(&mut self, sql: &str, params: &[BindValue])
    -> Result<Vec<DbRow>, sqlx::Error>;
pub async fn fetch_one(&mut self, sql: &str, params: &[BindValue])
    -> Result<DbRow, sqlx::Error>;
pub async fn fetch_optional(&mut self, sql: &str, params: &[BindValue])
    -> Result<Option<DbRow>, sqlx::Error>;
pub async fn execute(&mut self, sql: &str, params: &[BindValue])
    -> Result<u64, sqlx::Error>;   // rows_affected directly; PgQueryResult is driver-typed
pub fn dialect(&self) -> Dialect;
pub fn in_transaction(&self) -> bool;
```

Binding is two private helpers, `bind_pg` and `bind_sqlite`, each one `match` over
`BindValue`. `DbExecutor` gains `fn dialect(&self) -> Dialect`.

`Database` becomes an enum over `PgPool`/`SqlitePool`, keeping `query_count`.
`Database::connect` picks the backend from the URL scheme: `postgres://`/`postgresql://`
→ Postgres, `sqlite://` or a path ending `.db`/`.sqlite`/`:memory:` → SQLite.
`Database::pool()` currently returns `&PgPool` and is used across the workspace —
**keep it, returning `Option<&PgPool>`** is too disruptive; instead keep
`pool()` returning `&PgPool` but *panicking with a clear message* on a SQLite
database, and add `sqlite_pool() -> Option<&SqlitePool>`. Raw-SQL call sites that
have not been ported yet therefore fail loudly rather than silently misbehaving.

`isolation_level_sql` is Postgres-only; on SQLite return `None`/skip, since SQLite
has no `SET TRANSACTION ISOLATION LEVEL`.

## Section 3 — `djangors-orm` port

- `FromRow::from_row(&DbRow)` replaces `from_row(&PgRow)`. **This is a breaking
  change to a public trait and is expected.**
- Delete all eight bind blocks in `queryset.rs`; pass `&[BindValue]` to `Conn`.
- `compile_expr_sql` takes a `Dialect` and uses `dialect.placeholder(i)` instead of
  hardcoded `format!("${}", idx)`, and `dialect.ilike()` instead of literal `ILIKE`.
- `aggregate`/`annotate` use `dialect.cast_float` instead of literal `::float8`.
- `decode_value` reads through `DbRow`'s accessors.
- `NullBindKind` collapses into `db::NullKind`; delete the local duplicate.

## Section 4 — `djangors-macros`

`from_row` generation emits `&djangors_orm::DbRow` and reads columns via the
`try_*_by_name` accessors instead of `row.try_get::<T, _>(name)`. The four generated
bind `match` blocks are deleted — generated `save`/`update`/`insert` build a
`Vec<BindValue>` instead.

Generated DDL/SQL must use the dialect's placeholder, so generated statements take
the dialect from the executor at runtime rather than embedding `$1` at macro-expansion
time.

## Section 5 — `djangors-migrations`

`sql_type_for` takes a `Dialect`. SQLite mapping:

| FieldKind | Postgres | SQLite |
| --- | --- | --- |
| Char/Email/Url/Slug | `VARCHAR(n)` | `TEXT` |
| Text/FileField | `TEXT` | `TEXT` |
| Integer (auto) | `SERIAL` | `INTEGER` (see PK note) |
| BigInt (auto) | `BIGSERIAL` | `INTEGER` (see PK note) |
| Integer/BigInt | `INTEGER`/`BIGINT` | `INTEGER` |
| Float | `DOUBLE PRECISION` | `REAL` |
| Decimal | `NUMERIC(p,s)` | `NUMERIC` |
| Boolean | `BOOLEAN` | `INTEGER` |
| Date/DateTime/Time | `DATE`/`TIMESTAMPTZ`/`TIME` | `TEXT` |
| Duration | `INTERVAL` | `TEXT` |
| Uuid | `UUID` | `TEXT` |
| Ip | `INET` | `TEXT` |
| Binary | `BYTEA` | `BLOB` |
| Json | `JSONB` | `TEXT` |

**PK note:** SQLite auto-increment requires exactly `INTEGER PRIMARY KEY
AUTOINCREMENT` — `BIGINT PRIMARY KEY` does *not* autoincrement. The column-definition
builder must special-case an auto primary key on SQLite to emit
`INTEGER PRIMARY KEY AUTOINCREMENT` and must not additionally emit a separate
`PRIMARY KEY (...)` table constraint for it.

## Scope

**In scope:** `djangors-db`, `djangors-orm`, `djangors-macros`, `djangors-migrations`,
and whatever mechanical `from_row`/`pool()` fallout is required in other crates purely
to keep the workspace compiling.

**Out of scope (do not attempt):** porting the ~555 raw `sqlx::query` call sites in
`djangors-admin`, `djangors-auth`, `djangors-rest`, `djangors-tasks`,
`djangors-contrib-*` to be dialect-aware. Those keep using `Database::pool()` and stay
Postgres-only for now; that is a follow-up slice. Do not rewrite their SQL.

## Definition of done

1. `cargo build --workspace --all-targets` clean.
2. `cargo clippy --workspace --all-targets -- -D warnings` clean.
3. `cargo test --workspace` — all previously-passing tests still pass against
   Postgres. **No existing test assertion may be weakened or deleted to make this
   pass.** The suite was 396 passing before this change.
4. A new test in `djangors-orm` that runs a real `QuerySet` round-trip (create table,
   insert, filter with a `q!` expression, read back) against an **in-memory SQLite**
   database, proving the dual path genuinely works end to end and not just that it
   compiles.
5. A new test asserting `sql_type_for` produces `INTEGER PRIMARY KEY AUTOINCREMENT`
   for an auto PK under `Dialect::Sqlite`.
