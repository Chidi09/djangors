# 9.6c — fix every remaining compile error in the doc-code-check harness

## Where this picks up

9.6b built a real, well-designed harness: `tools/doc-code-check` (new workspace member,
`Cargo.toml`/`Cargo.lock` already updated) whose `build.rs` walks every `.md` file under
`docs/src/`, extracts every ` ```rust,compile ` fence (stripping rustdoc-style `# `-prefixed hidden
setup lines the same way real rustdoc doctests work), and generates one Rust module per snippet
into `OUT_DIR/generated_snippets.rs`, which `src/lib.rs` includes via `include!`. It correctly
panics at build time on any bare ` ```rust ` fence or unrecognized tag. Every existing Rust-fenced
block across every `docs/src/*.md` file (tutorial parts, topic guides, django-comparison, how-tos)
was already classified as `rust,compile` or `rust,illustrative`, and most got a hidden-line prelude
(a `# `-prefixed line defining supporting structs/imports the visible snippet depends on) so they'd
compile standalone. **Do not redesign or rewrite this mechanism — it's sound.** The dispatch that
built it died mid-verification before finishing the fix-up pass; your job is to finish that pass.

## The real, current problem

`cargo check -p doc-code-check` currently fails with **67 real compile errors**. Reproduce this
yourself first (`cargo check -p doc-code-check 2>&1 | tee /tmp/doc-check-errors.log`) to get the
exact, current, authoritative list — don't rely solely on the summary below, which was captured at
one point in time and its exact line numbers may drift as you make fixes.

Breakdown by error class (41+10+4+4+3+1+1+1+1 = 67 total, from the last known-good capture):
- **41× `cannot find attribute` X in this scope** — overwhelmingly `#[djangors(...)]` field
  attributes used on a struct whose own paired `#[derive(djangors_macros::Model, ...)]` isn't
  actually attached to that same struct within its generated module. This is the dominant error
  class — find and fix the root cause, not each occurrence individually if there's a systemic
  cause. One confirmed concrete instance: `docs/src/django-comparison.md`'s View Handlers section
  (§3) has a hidden-line prelude that duplicates the exact same `#[derive(djangors_macros::Model,
  Debug, Clone)]` + `#[djangors(app = "library", table_name = "library_article")]` pair twice in a
  row before `pub struct Article { ... }` — check whether that duplication (or a similar
  misalignment elsewhere) is why the derive isn't landing on the struct it should be on.
- **10× `unresolved import`**, **4× `cannot find module or crate`**, **1× `cannot find type`**,
  **1× `cannot find trait`** — snippets referencing an item without the right `use` statement in
  their own hidden prelude, or referencing something under the wrong path (e.g. `ServiceBuilder`
  needs `use tower::ServiceBuilder;` in whichever snippet's prelude is missing it, confirmed as one
  of the 67).
- **4× (E0255) + 1× (E0252) `the name X is defined multiple times`** — duplicate definitions,
  likely from copy-pasted hidden-line preludes across different snippets that happen to share a
  struct name (e.g. multiple snippets each defining their own `Question`/`Article`) — each
  generated module is already isolated in its own `pub mod snippet_...`, so a same-named struct in
  two DIFFERENT snippets should never collide; a same-name collision means duplication *within one
  snippet's own generated module* (the exact duplicate-prelude bug pattern above).

## How to fix

For each error, find the exact source `.md` file and line (the generated file's own comments/module
names encode the original file path, e.g. `snippet_docs_src_guides_auth_md_9` means
`docs/src/guides/auth.md` around line 9 — cross-reference against the real file). Fix the actual
Markdown source (the hidden `# `-prefixed lines and/or the visible snippet), never hand-edit the
generated `OUT_DIR` file (it's regenerated by `build.rs` every time, any manual edit there is
worthless). Common fixes:
- Remove a duplicated attribute/derive pair if one exists (the Article-model duplication above is a
  known instance — check for the same pattern elsewhere).
- Add a missing `use` line to a snippet's hidden prelude (e.g. `# use tower::ServiceBuilder;`).
- If two snippets in *different* files each define a same-named helper struct (e.g. both define
  `Question`), that's fine as long as each is correctly isolated inside its own snippet's module —
  a same-name error only happens if duplication occurs *inside a single generated module*, so trace
  back to which single snippet has the duplicate.

Work through every one of the 67 errors until `cargo check -p doc-code-check` is completely clean.
