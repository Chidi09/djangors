# 13.4 — Documentation pass (source comments + new topic guides)

## Why

Every crate is `#![deny(missing_docs)]`, so every *public* item already has a `///`. What is
missing is everything else: why a non-obvious block works the way it does, what a private helper
is for, and which subsystems have no prose guide at all. Measured doc-line-to-code-line ratio
per crate (excluding blank lines, counting `///`/`//!` as doc and `//` as comment):

| Crate | Code lines | `///`/`//!` | `//` | Doc % |
| --- | --- | --- | --- | --- |
| djangors-admin | 9074 | 135 | 210 | **1.5** |
| djangors-views | 559 | 15 | 14 | **2.7** |
| djangors-cache | 519 | 22 | 0 | **4.2** |
| djangors-macros | 1655 | 79 | 25 | **4.8** |
| djangors-tasks | 1082 | 53 | 37 | **4.9** |
| djangors-cli | 1881 | 96 | 52 | **5.1** |
| djangors-sessions | 610 | 32 | 21 | **5.2** |

| djangors-template | 925 | 66 | 12 | **7.1** |
| djangors-contrib-contenttypes | 192 | 14 | 0 | **7.3** |

For contrast the best-documented crates sit at 22–43% (`djangors-deploy`, `djangors-pdf`,
`djangors-forms`, `djangors-contrib-messages`). `djangors-admin` is both the largest crate in the
workspace and the least documented, by a wide margin.

## Part A — source comments

Target the ten crates above, worst-first. The goal is **explanatory** comments, not restatement.

Good:
```rust
// A HashMap extractor silently drops all but the last value for repeated form keys, which is
// exactly what multiple checked "selected" checkboxes produce — hence Vec<(String, String)>.
```

Worthless, do not write:
```rust
// Increment the counter
counter += 1;
```

Priority within each crate:
1. Module-level `//!` headers explaining what the module is for and how its pieces fit.
2. Private functions and helpers — currently the least documented category.
3. Non-obvious logic: escaping decisions, SQL construction, lifetime/borrow workarounds,
   protocol-level quirks, anything with a "why is it like this" answer that is not on the page.
4. Struct fields whose meaning is not obvious from the name.

Several such rationales already exist only in `CHANGELOG.md` or `docs/design/*.md` and should be
brought to the code they describe — for example the `Vec<(String, String)>`-vs-`HashMap` form
extractor decision, the `html_escape` `&#x2F;`-uppercase vs minijinja `&#x2f;`-lowercase
discrepancy, and why `Conn` uses enum dispatch instead of generics over `sqlx::Database`.

**Hard constraint: comments and doc comments only.** No logic changes, no renames, no
reformatting, no reordering. The review gate is that every added or removed line in a `.rs` file
is a comment line or a blank line. A single changed line of real code fails the slice.

## Part B — new topic guides

`docs/src/guides/` has 14 guides but nothing for several shipped subsystems. Add:

| New file | Covers |
| --- | --- |
| `guides/databases.md` | **The 13.1–13.3 dual-backend story**, currently undocumented anywhere |
| `guides/migrations.md` | `dj makemigrations`/`dj migrate`, `Operation`, rollback, snapshots |
| `guides/tasks.md` | `#[task]`, the worker, recurring/cron jobs, `SKIP LOCKED` claiming |
| `guides/caching.md` | `Cache` trait, the three backends, `CacheLayer` opt-in |
| `guides/i18n.md` | Fluent catalogs, fallback chain, the `trans` filter |
| `guides/sessions.md` | Signed-cookie engine, CSRF interaction |
| `guides/static-files.md` | Dev serving, `collectstatic`, hashed manifest |
| `guides/signals.md` | Request and model signals |

`guides/databases.md` is the highest-value one and must be written first: it is the only place a
user would learn that SQLite is supported, how `DATABASE_URL` selects the backend, which parts are
dialect-aware, and that `djangors-test` remains Postgres-only.

Each new guide must be added to `docs/src/SUMMARY.md` under `# Topic Guides` or mdbook will not
render it.

### Code block rules — this breaks the build if violated

`tools/doc-code-check/build.rs` parses every `.md` under `docs/src/` and **hard-errors** on a bare
` ```rust ` block. Every Rust block must be tagged exactly one of:

- ` ```rust,compile ` — extracted and compiled as a real module. It must actually compile against
  this workspace. Lines prefixed `# ` are hidden from rendered output but included in compilation.
- ` ```rust,illustrative ` — rendered but never compiled. Use for fragments and pseudo-code.

Anything else (` ```rust `, ` ```rs `, ` ```rust,ignore `) is a build error. When unsure whether a
snippet compiles, tag it `rust,illustrative` — a wrong `rust,compile` tag breaks the workspace
build for everyone.

## Scope

**In scope:** comments/doc-comments in the ten crates listed; new `.md` files under
`docs/src/guides/`; `docs/src/SUMMARY.md`.

**Out of scope:** any logic change; any change under `crates/*/src` that is not a comment;
rewriting existing guides; `README.md`; the marketing site under `site/`.

## Definition of done

1. `cargo build --workspace --all-targets` clean.
2. `cargo clippy --workspace --all-targets -- -D warnings` clean.
3. `cargo test --workspace` — all 405 tests still pass, none weakened or removed.
   `doc-code-check` passing is what proves every `rust,compile` block is real.
4. `cargo doc --workspace --no-deps` builds without warnings.
5. Every `.rs` diff line is a comment or blank line — verifiable with
   `git diff -U0 -- '*.rs'`.
6. All eight new guides exist, are listed in `SUMMARY.md`, and every Rust block in them is tagged
   `rust,compile` or `rust,illustrative`.
