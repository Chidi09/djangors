# 15.2 — Named routes, `reverse()`, and the missing template tags

Status: design, 2026-07-31.

## Why

Two `PLAN.md` items that turn out to be one problem.

Phase 1 asked for "named routes with `reverse!()`". It was never built: there is no route-name
registry and no reverse lookup anywhere in the workspace. Every link in user code is a hardcoded
string, so changing a URL pattern silently breaks every template that referenced it.

Phase 3 asked for the tags `{% url %}`, `{% static %}`, `{% csrf_token %}`, `{% now %}`.
`djangors-template` registers **no** globals or functions at all — only filters. So all four are
absent. `{% url %}` was blocked on named routes; the other three were not blocked on anything.

`{% csrf_token %}` is the one with a real safety cost. CSRF form-body validation works
(5.8.9/5.8.10), but a user writing a plain `<form>` has to thread the token through their context
by hand and hand-write the hidden input. Forgetting is silent at render time and only shows up as
a rejected POST — or, worse, gets "fixed" by exempting the view.

## Constraint discovered before designing: minijinja has no custom tags

`djangors-template` is built on minijinja 2.21. Its `Environment` exposes `add_filter`,
`add_function`, and `add_global` — there is **no public API for custom statement tags**. Verified
against `minijinja-2.21.0/src/environment.rs`.

So `{% url 'name' %}` in Django's syntax is not implementable here. What is implementable is
function-call syntax:

```
{{ url('poll-detail', id=1) }}
{{ static('css/app.css') }}
{{ csrf_token() }}
{{ now('%Y') }}
```

**This must be documented as function syntax, not tag syntax.** Writing `{% static %}` anywhere in
the guides would be a fabrication that fails the moment a user copies it. The Django-comparison
guide should note the difference explicitly rather than papering over it.

## Part 1 — named routes (`djangors-core`)

### Data

`Route` (`router.rs:46`) gains one field:

```rust,illustrative
struct Route {
    pattern: String,
    method: Method,
    segments: Vec<Segment>,
    param_names: Vec<String>,
    handler: HandlerKind,
    name: Option<String>,     // new
}
```

Every existing `Route { .. }` construction site must set it. There are at least two: `route()` and
`mount()`. Miss the one in `mount()` and names silently vanish for every mounted sub-router, which
is exactly the case most likely to be under-tested.

### API — name the route just registered

```rust,illustrative
Router::new()
    .get("/polls/{id}", detail).name("poll-detail")
    .get("/polls/", index).name("poll-index")
```

`Router::name(mut self, name: &str) -> Self` sets the name on the most recently pushed route. This
keeps the diff small and reads naturally. **Panic if called on an empty router** — that is a
programming error, and `route()` already panics on a bad pattern, so it matches existing behaviour.

**Panic on a duplicate name at registration time.** Last-wins would make a copy-paste error
resolve to the wrong URL at runtime, which is far harder to diagnose than a startup panic. Django
tolerates duplicates via namespacing; namespacing is out of scope for v1, so refuse instead.

### Reverse

```rust,illustrative
pub fn reverse(&self, name: &str, params: &[(&str, &str)]) -> Result<String, ReverseError>;
```

Rebuild the path by walking the route's `segments`, substituting each capture from `params`.
Return a leading-slash absolute path (`/polls/1`).

```rust,illustrative
pub enum ReverseError {
    UnknownName(String),
    MissingParam { route: String, param: String },
    UnexpectedParam { route: String, param: String },
}
```

Requirements:

- **Mounted routes reverse to their full path.** `mount()` rewrites `pattern` and re-parses
  segments, so as long as `name` is carried through, this falls out for free — but it needs a test,
  because it is the case that breaks if the `mount()` construction site is missed.
- **Percent-encode substituted values.** A param containing `/`, `?`, `#`, or a space must not be
  able to forge path structure. Values arrive from application code, but application code routinely
  passes user-controlled slugs. Use percent-encoding for the path segment set; do not hand-roll a
  replace list.
- Reject a param not present in the pattern rather than silently ignoring it — a typo'd key should
  not produce a URL missing the value the caller thought they supplied.
- `reverse` on a route with a typed converter (`{id:i64}`) does **not** need to validate the type in
  v1, but must not crash on a non-numeric value. Note the limitation in the doc comment.

## Part 2 — template functions (`djangors-template`)

### The dependency problem, and the fix

`djangors-template` must not depend on `djangors-core` — core already sits above template in the
graph, and adding the reverse edge creates a cycle. So the engine cannot call `Router::reverse`
directly.

Instead the engine accepts an injected resolver. The wiring crate (whoever owns both the router and
the engine) supplies a closure that closes over the `Router`:

```rust,illustrative
impl TemplateEngine {
    /// Supply the resolver backing `{{ url(...) }}`.
    pub fn set_url_resolver<F>(&mut self, f: F)
    where
        F: Fn(&str, &[(String, String)]) -> Option<String> + Send + Sync + 'static;

    /// Prefix for `{{ static(...) }}`. Defaults to "/static/".
    pub fn set_static_url(&mut self, prefix: &str);
}
```

If no resolver is set, `{{ url(...) }}` must return a **template error**, not an empty string. A
silently empty `href=""` is a broken link that renders fine and is found by a user, not a test.

### The four functions

| Call | Behaviour |
|---|---|
| `{{ url('name', k=v, ...) }}` | Resolver lookup; error if unset or unknown name |
| `{{ static('css/app.css') }}` | `static_url` prefix + path, joined with exactly one `/` |
| `{{ csrf_token() }}` | Renders `<input type="hidden" name="csrfmiddlewaretoken" value="…">` |
| `{{ now('%Y-%m-%d') }}` | Current UTC time formatted with the given `chrono` format string |

### `csrf_token()` is the one with sharp edges

Two escaping mistakes are both easy and both bad:

1. The returned HTML must be marked safe (`Value::from_safe_string`), or auto-escaping turns the
   `<input>` into visible text. Auto-escape is on for `.html`/`.htm` (`engine.rs:16`).
2. The **token value itself must be HTML-attribute-escaped before** being placed in the `value="…"`
   attribute. Marking the whole string safe after interpolating an unescaped token would let a
   crafted token break out of the attribute. Escape the token, then mark the assembled element
   safe — in that order.

The function reads the token from the render context (the `csrf_token` variable). If it is absent,
return a template **error** naming the missing context key. Rendering an empty
`value=""` would produce a form that silently fails every POST, and the natural "fix" a user
reaches for is to disable CSRF on the view.

`djangors-template` must not gain a dependency on `djangors-core` for this — the token is a plain
string in the context, so no type import is needed.

## Testing

- `reverse` round-trips: register a route, reverse it, and assert the result matches what the
  router actually matches. A pure-string assertion can pass while the router disagrees; asserting
  both directions is what makes this meaningful.
- Reverse a route registered inside a `mount()`ed sub-router — the regression case for the missed
  construction site.
- Unknown name, missing param, and unexpected param each produce their distinct error.
- A param containing `/` and a space is percent-encoded, not interpolated raw.
- Duplicate name panics at registration.
- `static()` joins correctly whether or not the prefix and path have slashes.
- `csrf_token()` output contains the token, is not double-escaped, and a token containing `"` and
  `<` cannot break out of the attribute.
- `url()` with no resolver set returns an error rather than an empty string.
- `now()` with an explicit format returns a parseable date.
