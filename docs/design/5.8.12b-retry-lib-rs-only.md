## Hard rule: never `git checkout`/`git restore`/`git reset` any file to undo a bad edit

This is what destroyed the first attempt's work. If an edit tool call fails
to match (stale line numbers, wrong lines, etc.), the fix is: **re-view the
current state of the file and issue a new, corrected, narrowly-scoped edit.**
Never run `git checkout <path>`, `git restore <path>`, or any `git reset`
against a file that has *any* uncommitted work in it — these revert the
**entire file** to the last commit, not just your last change, and there is
no undo (not in reflog, not in stash — plain working-tree edits are not
tracked by git at all until staged/committed).

If you are ever unsure whether a file has uncommitted work you'd lose,
run `git diff --stat <path>` first and look at the actual line count, not
just `git status`.
